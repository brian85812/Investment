# Telegram 動作摘要（2026-11-08）

依 Brian 要求，推播以「本次是否有需核對的動作」開頭，每市場一行。新目標列前後倍數；模擬修剪列實帳判斷門檻及目標；過期或來源失敗市場列暫停調倉指示及原因。冷卻僅列一次剩餘市場交易日，轉倉剩五日內保留簡短提醒。均線、通道與歷史紀錄留在儀錶板。

目前未知個人實帳是否超標，因此無新訊號時用「無新增調倉」，並保留實帳超標核對條件，不能解讀為已確認個人帳戶無須操作。各市場都標明行情日期，休市日不冒稱為當日行情。目標變更與模擬超標修剪可同時列出。

推播頻率、事件識別與去重、靜音規則、降級市場事件不消耗、送達後才記錄、失敗重試及部署後發送流程沿用既有機制。結算兩日內、資料降級、新訊號或新模擬修剪為有聲提醒。

## 範例（11/6 快照，尚未通知事件）

```text
🔔 本次有待核對動作
• 美股 11/06：維持 0.80x
• 台股 11/06：模擬超標修剪提醒：實帳 >2.95x 才降回 2.80x（減碼後冷卻餘 5 交易日）
實帳超過目標+0.15x仍須核對修剪；詳情看儀錶板。
```

49 個 Python 測試通過，包含同時新目標及模擬修剪、單市場過期但另一市場有新訊號、換約到期與摘要長度。原通知案例保留，只有歷史詳細文字與重複狀態的顯示期待配合本次需求改寫。相同真實快照的新舊可見文字由 721 字降至 111 字，約 15.4%；新舊 HTTP 均為離線攔截，本機未傳送真實 Telegram。
